# UX 명세

> 상태: 설계 승인
> 기준일: 2026-08-15
> 구현 상태: 미구현

상태별 Mobile·Desktop 정보 계층과 컴포넌트 동작은
[반응형 Low-fidelity Wireframe](WIREFRAMES.md)을 단일 기준으로 사용한다.

## 1. 경험 목표

사용자는 여행 전문가처럼 조건을 작성할 필요 없이 3분 안에 입력을 마치고,
결과가 단순 추천 목록이 아니라 실제 하루 일정임을 한눈에 이해해야 한다.
출처와 이동시간의 불확실성은 숨기지 않고 필요한 위치에서 설명한다.

## 2. 핵심 화면

### A. 시작·조건 입력

- 도시 선택: 서울, 도쿄
- 일정: 시작일, 1~4박, 도착·출발 시간
- 누구와: 혼자, 친구, 연인, 가족
- 하고 싶은 것: 감성, 음식, 쇼핑, 자연, 문화, 야경 등 복수 선택
- 여행 성향: 느림·보통·빠름, 예산, 걷기 허용량
- 장소 조건: 필수 방문, 제외 장소
- 고급 조건: 비 오는 날, 접근성, 식이 조건은 접힌 영역
- 주 행동: 조합하기

필수 입력을 먼저 보여주고 세부 조건은 점진적으로 공개한다. 자유서술 입력은
MVP에서 보조 기능이며 선택형 입력만으로 전체 기능을 사용할 수 있어야 한다.

### B. 계산 중

- 단계 텍스트: 조건 확인, 지역 묶기, 시간표 구성, 근거 연결
- 10초 이상 걸릴 경우 재시도와 조건 수정 제공
- 장식용 퍼센트가 아니라 실제 완료 단계만 표시
- 화면낭독기에 polite live region으로 상태 전달

### C. 일정 결과

상단에는 여행 요약, 데이터 확인일, 일정 적합도, 총 이동시간 추정과 새 조합을
배치한다. 본문은 날짜 탭이 아닌 세로 일자 섹션을 기본으로 하여 인쇄와 모바일
탐색을 쉽게 한다.

각 Day Plan은 다음 순서를 가진다.

1. 날짜와 하루 테마
2. 지도 또는 단순 경로 개요
3. 시간순 Visit 카드
4. Visit 사이 Travel Segment
5. 하루 이동·보행·여유시간 요약
6. 일정상 주의사항

### D. 출처 상세

Visit 카드의 근거 보기 버튼은 같은 화면의 Disclosure 또는 Bottom Sheet를 연다.
출처 유형, 제공자, 확인일, 어떤 판단을 뒷받침하는지와 원문 링크를 보여준다.
제3자 원문은 프레임으로 삽입하지 않고 새 탭에서 연다.

### E. 방법론·정책

추천 방식, 점수 항목, 이동시간의 의미, 출처 등급, 정정 요청과 비영리 운영
원칙을 독립된 정적 페이지에서 설명한다.

## 3. 입력 규칙

| 입력 | 기본값 | 검증 |
|---|---|---|
| 도시 | 없음 | 서울 또는 도쿄 필수 |
| 시작일 | 없음 | 오늘부터 365일 이내 필수 |
| 박수 | 2박 | 1~4박 |
| 도착 | 첫날 10:00 | 출발보다 앞서야 함 |
| 출발 | 마지막날 18:00 | 여행 범위 안 |
| 동행 | 친구 | 1개 |
| 테마 | 없음 | 최소 1개 권장, 없어도 기본 조합 가능 |
| 속도 | 보통 | 느림·보통·빠름 |
| 걷기 | 보통 | 적게·보통·많이 |
| 예산 | 보통 | 절약·보통·여유 |
| 필수 장소 | 없음 | 도시 일치, 최대 4개 |
| 제외 장소 | 없음 | 필수 장소와 중복 불가 |
| 우천 고려 | 끔 | 켜면 검수된 실내 대체 후보를 계산 |

오류는 필드 가까이에 원인과 수정법을 함께 표시하고 첫 오류로 포커스를 옮긴다.
사용자 입력은 오류 후에도 유지한다.

## 4. 결과 카드 명세

Place 카드에는 다음 정보만 우선 노출한다.

- 장소명과 지역
- 방문 예정 시간과 체류시간
- 선택 이유 최대 2개
- 예상 비용 수준과 실내·실외
- 근거 등급 배지와 확인일
- 근거 보기, 공식 사이트, 지도에서 확인
- 우천 대체 가능 여부와 교체 시 이동시간 영향

추천 점수 숫자를 절대 품질처럼 강조하지 않는다. 점수는 근거 상세에서
테마 적합, 동행 적합, 동선 효율, 근거 신뢰와 최신성 구성으로 설명한다.

## 5. 새 조합

- 필수 장소, 제외 장소, 도시와 여행시간은 유지한다.
- 다양화 Seed를 변경하고 상위 유효 후보 안에서 다시 계산한다.
- 바뀐 장소를 요약하고 이전 결과로 한 단계 되돌리기를 제공한다.
- 유효 대안이 없으면 같은 결과를 숨겨 바꾸지 않고 이유를 표시한다.

## 6. 상태와 오류

| 상태 | 사용자 메시지 | 행동 |
|---|---|---|
| 후보 부족 | 어떤 조건이 후보를 줄였는지 설명 | 걷기·테마·필수 장소 수정 |
| 일정 불가능 | 충돌 장소와 시간 표시 | 필수 해제 또는 시간 수정 |
| API 제한 | 잠시 후 재시도 안내 | 입력 유지, 지수 백오프 |
| 지도 장애 | 일정은 정상 제공 | 외부 지도 링크 제공 |
| AI 장애 | 규칙 기반 설명 제공 | 별도 오류 노출 최소화 |
| 오래된 데이터 | 확인일과 주의 배지 | 공식 사이트 재확인 |
| 출처 비활성 | 해당 근거를 숨기고 신뢰 재계산 | 대체 근거 표시 |

## 7. 모바일·반응형

- 360px에서 수평 스크롤 없이 핵심 흐름을 완료한다.
- 결과는 한 열 타임라인, 지도는 접을 수 있는 고정 비율 영역으로 제공한다.
- 데스크톱은 일정과 지도를 60:40으로 배치하되 읽기 순서를 바꾸지 않는다.
- 터치 목표는 최소 44x44 CSS px를 목표로 한다.
- Bottom Sheet는 키보드 사용 시 일반 Dialog 규칙을 따른다.

## 8. 접근성

- 모든 입력은 영구 Label과 오류 설명을 가진다.
- 색상 외에 텍스트와 아이콘 모양으로 근거 등급을 구분한다.
- 일정 선과 지도 없이도 시간 순서를 이해할 수 있다.
- 지도 마커 정보는 동일한 순서의 텍스트 목록으로 제공한다.
- 동적 계산 상태와 오류를 live region으로 알린다.
- reduced-motion 환경에서 전환 애니메이션을 제거한다.
- 한국어·일본어 장소명의 읽기 가능한 대체 표기를 데이터 모델에서 지원한다.

## 9. 개인정보와 신뢰

- 현재 위치 권한을 요구하지 않는다.
- 계정이나 브라우저 식별자를 만들지 않는다.
- 자유서술이 추가되더라도 저장하지 않고 요청 처리 후 폐기한다.
- 출처 링크는 외부 사이트 이동임을 알린다.
- 이동시간은 계획용 추정이며 출발 전 공식 교통정보 확인이 필요함을 표시한다.

## 10. UX 인수 조건

- 키보드만으로 조건 입력, 조합, 새 조합, 근거 열기가 가능하다.
- 결과 첫 화면에서 도시, 날짜, 일정 적합 여부와 총 이동 추정을 확인할 수 있다.
- 모든 Visit은 근거 상세로 연결된다.
- 지도 비활성 상태에서도 일정 이해와 외부 경로 이동이 가능하다.
- 오류가 발생해도 사용자가 입력한 조건은 사라지지 않는다.

## 11. 화면 상태 전이

~~~mermaid
stateDiagram-v2
    [*] --> Editing
    Editing --> Validating: 조합하기
    Validating --> Editing: 입력 오류
    Validating --> Composing: 유효한 요청
    Composing --> Result: 일정 생성 성공
    Composing --> RecoverableError: 후보 부족·일시 오류
    Composing --> RateLimited: 사용량 제한
    RecoverableError --> Editing: 조건 수정
    RecoverableError --> Composing: 재시도
    RateLimited --> Editing: 입력 유지
    Result --> Editing: 조건 수정
    Result --> Composing: 새 조합
~~~

중복 요청 방지를 위해 Composing 중 `조합하기`를 비활성화한다. Result가 표시되기
전 기존 입력을 폐기하지 않으며, 실패 상태는 오류 코드보다 사용자가 수정할 조건과
다음 행동을 먼저 설명한다.
