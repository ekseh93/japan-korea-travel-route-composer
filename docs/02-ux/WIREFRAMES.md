# 반응형 Low-fidelity Wireframe

## 문서 통제

| 항목 | 내용 |
|---|---|
| 문서 ID | `TRC-UX-002` |
| 버전 | `v1.0` |
| 상태 | BASELINED |
| 대상 | 360px Mobile, 768px Tablet, 1280px 이상 Desktop |
| 구현 상태 | LUN-010 Web 구현 및 접근성·반응형 브라우저 E2E 완료; 별도 픽셀 시각 QA 미실행 |

이 문서는 정보 계층과 상태별 상호작용 계약이다. 픽셀 단위 시안은 아니며, Luna는
이 구조를 유지하면서 실제 컴포넌트와 접근성 동작을 구현한다. 공개 DTO는
[API 계약](../04-architecture/API_CONTRACT.md), 선택값은
[Domain Catalog](../05-data/DOMAIN_CATALOG.md)를 따른다.

## 1. 시각 방향

`편집된 여행 잡지 + 교통 노선도`를 기본 방향으로 한다. 평면적인 흰색 카드 모음이나
보라색 중심 SaaS 화면을 피하고, 따뜻한 종이색 배경 위에 짙은 잉크색 본문, 도시별
노선색, 얇은 격자·경로선을 사용한다. 지도는 장식이 아니라 일정의 공간적 검증
수단이며, 지도 없이도 같은 정보를 읽을 수 있어야 한다.

| Token 역할 | 기준 |
|---|---|
| Canvas | 따뜻한 저채도 배경과 매우 옅은 지도 격자 |
| Ink | 본문·경계에 사용하는 짙은 남청색 |
| Tokyo accent | 주홍색 계열, 색상 외 `東京/TOKYO` Label 병기 |
| Seoul accent | 청록색 계열, 색상 외 `서울/SEOUL` Label 병기 |
| Evidence | Tier 문자와 아이콘을 함께 사용, 색만으로 구분 금지 |
| Warning | 호박색 면과 명시적 `주의` 문구 |

언어별 제목은 한국어 `Gowun Batang`, 일본어 `Shippori Mincho`, 영어
`Source Serif 4` 계열을 우선 검토한다. 본문은 한국어 `SUIT`, 일본어
`BIZ UDPGothic`, 영어 `Source Sans 3` 계열을 검토한다. Luna는 실제 배포 전
라이선스·한글/가나 Coverage를 확인하고 subset을 적용하며 전체 Font 전송 예산을
250 KiB 이하로 맞춘다. Font 사용이 불가능하면 Layout shift 없는 명시적 Fallback을
사용하되 기본 System stack을 시각 정체성으로 삼지 않는다.

## 2. Breakpoint와 공통 Shell

| 범위 | Layout 계약 |
|---|---|
| 360~767px | 한 열, 16px Gutter, 지도 접힘, 하단 고정 주 행동 |
| 768~1279px | 한 열 중심, 입력 Group 2열 허용, 지도 전체 폭 |
| 1280px 이상 | 최대 1440px, 결과 Timeline 60% + 지도 40% Sticky |

Header에는 서비스명, `추천 방식`, `출처 정책`, 언어 선택을 둔다. Skip link는
`본문으로 건너뛰기`와 결과가 존재할 때 `일정으로 건너뛰기`를 제공한다. Footer에는
비영리 목적, 정정 요청, 데이터 확인 책임과 Repository 링크를 둔다.

- Section 완료 여부를 숫자 옆 Text로 알리고 필수 오류는 해당 Section 안에 표시한다.
- Mobile 하단 주 행동은 키보드가 열리면 고정하지 않아 입력을 가리지 않는다.
- `필수·제외 장소`는 Catalog 검색 결과만 선택하며 자유 문자열을 PlaceId로 보내지 않는다.
- 자유서술은 P1 AI Adapter가 활성화되기 전 숨긴다. 선택형 입력만으로 조합 가능하다.
- 조합 직전 Request 요약을 보이지 않는 값까지 Screen reader가 확인할 수 있게 한다.

## 4. Mobile 계산 중

~~~text
┌──────────────────────────────────┐
│ ← 조건 수정      조합하는 중     │
├──────────────────────────────────┤
│        ╭──── 노선 애니메이션     │
│        ●━━●━━○━━○                │
│                                  │
│ ✓ 조건 확인                      │
│ ✓ 방문 지역 묶기                 │
│ ● 영업시간과 이동시간 계산       │
│ ○ 추천 근거 연결                 │
│                                  │
│ 입력은 이 기기에 유지됩니다.     │
│ [10초 후 표시: 다시 시도]        │
└──────────────────────────────────┘
~~~

가짜 Percent를 표시하지 않는다. 진행 단계는 실제 Application 단계 Event가 있을 때만
변경한다. 애니메이션은 경로가 완성되는 한 번의 전환만 사용하고 `prefers-reduced-motion`
에서는 정적 상태로 바꾼다. `조합하기` 재클릭은 막고 Abort 후 조건 수정은 허용한다.

- `공식 사이트`와 `지도에서 확인`은 외부 이동 아이콘 및 새 탭 안내를 포함한다.

만들고 Escape와 닫기 버튼을 지원한다. 외부 페이지를 iframe으로 삽입하지 않는다.

## 7. 실패·빈 상태

### 일정 불가능

~~~text
┌──────────────────────────────────┐
│ 이 조건으로는 일정을 만들 수 없음│
│ 필수 장소 A가 선택 날짜에 휴무라 │
│ 시간 조건을 만족하지 않습니다.   │
│                                  │
│ [필수 장소 해제] [조건 수정]      │
│ [공식 운영정보 확인 ↗]            │
└──────────────────────────────────┘
~~~

### 일시 장애·사용량 제한

입력을 유지하고 재시도 가능 시각과 `다시 시도`를 표시한다. API ErrorCode를 제목으로
노출하지 않는다. `RATE_LIMITED`는 자동 반복 요청하지 않으며 `CATALOG_UNAVAILABLE`은
일정 대신 오래된 결과를 임의 제공하지 않는다.

### 지도 장애

Timeline 전체는 정상 표시한다. 지도 영역에 `지도를 불러오지 못했습니다`와 각
Travel Segment의 외부 길찾기 링크를 제공하며, 조합 성공 자체를 실패로 바꾸지 않는다.

### 대안 없음

새 조합 결과가 기존과 70% 넘게 겹치고 유효한 다른 후보가 없으면 같은 결과를 새것처럼
표시하지 않는다. `현재 조건에서는 충분히 다른 동선이 없습니다`와 조건 수정 행동을
제공한다.

## 9. 상태별 컴포넌트 계약

| 컴포넌트 | 상태 | 필수 동작 |
|---|---|---|
| Composer | pristine, invalid, valid, submitting | Invalid은 inline 설명·오류 요약·Focus 이동 |
| ComposeButton | enabled, disabled, pending | Pending 중 중복 제출 차단, 상태 Text 유지 |
| Result | success, impossible, transientError | 입력 유지, Error별 복구 행동 제공 |
| VisitCard | default, expanded, unavailable | 근거 없는 PUBLISHED Visit 렌더링 금지 |
| EvidencePanel | closed, open, sourceUnavailable | Focus trap·원문 링크·확인일 제공 |
| RouteMap | loading, ready, failed | Failed여도 Timeline과 외부 링크 유지 |
| Regenerate | ready, pending, noAlternative | 기존 결과 유지 후 성공 시 교체 |
| Language | ko, ja, en, fallback | Locale 변경 시 PlaceId·시간·Seed 유지 |

## 10. 접근성·Content QA 주석

- Heading은 페이지 H1, Section H2, Day H3, Visit H4 순서를 유지한다.
- 모든 Icon button에 보이는 Label 또는 접근 가능한 이름을 제공한다.
- 200% Zoom과 360px에서 Text·버튼이 잘리거나 겹치지 않는다.
- 44x44 CSS px Touch target과 명확한 Focus indicator를 적용한다.
- 도시·Evidence·Warning은 색 외 Text Label로 구분한다.
- `약`, `추정`, `확인일`을 생략해 이동시간·가격·운영정보를 확정값처럼 보이지 않는다.
- 한국어·일본어·영어 30% 긴 번역 Fixture로 Layout을 검증한다.
- Page load에는 Hero와 Form의 짧은 순차 Reveal 하나만 허용하고 결과 조작에는 과도한
  Motion을 사용하지 않는다.

## 11. UI 인수 조건

- [ ] 360px, 768px, 1280px에서 입력부터 근거 확인까지 수평 Scroll 없이 완료한다.
- [ ] Keyboard만으로 조합, 오류 수정, 새 조합, 근거 Dialog, 외부 확인을 수행한다.
- [ ] API의 모든 ErrorCode가 입력을 보존하는 명시적 UI 상태로 Mapping된다.
- [ ] 지도·AI 장애가 일정 Timeline을 제거하지 않는다.
- [ ] 모든 VISIT은 RecommendationReason과 Tier A/B Evidence를 표시한다.
- [ ] 동일 DTO가 Mobile과 Desktop에서 같은 정보 순서와 의미를 유지한다.
- [ ] ko/ja/en 긴 문자열과 Screen reader 수동 검증을 Release 증거로 남긴다.
- [ ] Lighthouse·axe 결과는 목표이며 실행 전 통과한 것으로 기록하지 않는다.

판정: `RESPONSIVE WIREFRAME BASELINED` - Luna는 LUN-010에서 이 구조를 구현하고
Responsive·Accessibility E2E 및 수동 검증으로 확정한다.
