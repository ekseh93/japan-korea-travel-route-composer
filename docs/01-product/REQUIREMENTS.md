# 요구사항 명세

> 상태: 설계 승인
> 기준일: 2026-08-15
> 구현 상태: 미구현
> 상위 업무 기준선: [업무·시스템 요건정의서](REQUIREMENTS_DEFINITION.md)

이 문서는 구현·테스트 가능한 원자적 `FR/NFR/AC`를 소유한다. 상위 업무목표,
RACI, 업무 규칙, 데이터·연계·운영·전환요건은 요건정의서를 따른다.

## 1. 기능 요구사항

| ID | 요구사항 | MVP |
|---|---|---|
| FR-001 | 사용자는 도쿄 또는 서울을 선택할 수 있다. | 필수 |
| FR-002 | 사용자는 시작일, 1~4박과 도착·출발 시간을 입력할 수 있다. | 필수 |
| FR-003 | 사용자는 동행, 테마, 예산, 속도와 걷기 허용량을 선택할 수 있다. | 필수 |
| FR-004 | 사용자는 필수 방문 장소와 제외 장소를 지정할 수 있다. | 필수 |
| FR-005 | 시스템은 잘못되거나 충돌하는 입력을 조합 전에 설명한다. | 필수 |
| FR-006 | 시스템은 조건에 맞지 않는 장소를 결정론적으로 제외한다. | 필수 |
| FR-007 | 시스템은 영업시간, 체류시간, 이동시간과 하루 시간 예산을 지킨다. | 필수 |

| FR-010 | 시스템은 장소별 추천 이유와 점수 구성 요소를 표시한다. | 필수 |
| FR-011 | 시스템은 장소별 근거 유형, 출처, 확인일과 원문 링크를 표시한다. | 필수 |
| FR-012 | 시스템은 이동시간이 추정치임을 표시하고 외부 길찾기 링크를 제공한다. | 필수 |

| FR-014 | 새 조합에서도 사용자가 지정한 필수 장소는 유지된다. | 필수 |

## 2. 비기능 요구사항

| ID | 품질 속성 | 요구사항 |
|---|---|---|

| NFR-002 | 성능 | 캐시 적중 시 조합 API p95 목표를 1초 이내, 미적중 시 5초 이내로 설계한다. 구현 후 측정 전까지 목표로만 표시한다. |
| NFR-003 | 가용성 | 외부 지도·AI 장애 시 일정 본문은 계속 제공한다. |
| NFR-004 | 결정성 | 데이터 버전, 알고리즘 버전, Seed가 같으면 기본 결과가 같아야 한다. |
| NFR-005 | 보안 | 공개 API는 입력 크기, 허용값, 요청 빈도를 제한하고 최소 권한 IAM을 사용한다. |
| NFR-006 | 개인정보 | MVP는 계정, 위치 추적, 광고 식별자와 자유서술 개인정보를 저장하지 않는다. |

| NFR-009 | 관측성 | 요청 ID, 결과 상태, 지연시간, 오류 유형을 개인정보 없이 기록한다. |

| NFR-014 | 복구성 | Terraform 상태 복구, 롤백, 캐시 무효화와 전체 철거 절차를 제공한다. |
| NFR-015 | 공급망 | Lockfile, 고정된 Actions commit SHA와 의존성 검사를 사용한다. |

## 3. 주요 인수 조건

### AC-001 기본 조합

Given 유효한 서울 2박, 친구, 음식·쇼핑, 보통 속도 조건이 있고
When 사용자가 조합하기를 누르면
Then 시스템은 3일 일정, 장소 순서, 체류시간, 이동시간, 추천 이유와 출처를 반환한다.

### AC-002 필수 장소

Given 필수 장소가 운영시간 안에 배치 가능하고
When 기본 조합과 새 조합을 각각 생성하면
Then 두 결과 모두 해당 장소를 정확히 한 번 포함한다.

### AC-003 충돌 조건

Given 필수 장소의 운영시간이 여행 가능 시간과 겹치지 않고
When 조합을 요청하면
Then 시스템은 일정을 생성한 것처럼 보이지 않고 충돌 이유와 수정 선택지를 표시한다.

### AC-004 출처 통제

Given Place의 Evidence가 BLOCKED 또는 REVIEW_REQUIRED 상태이고
When 공개 Seed를 생성하면
Then 해당 Evidence는 공개 산출물에서 제외되고 검증은 실패 원인을 보고한다.

### AC-005 외부 서비스 장애

Given 지도 타일 또는 선택적 AI 제공자가 응답하지 않고
When 사용자가 기존 조건으로 조합하면
Then 일정과 규칙 기반 추천 이유는 제공되고 실패한 부가 기능만 안내된다.

### AC-006 결정성

Given 입력, 데이터 버전, 알고리즘 버전과 다양화 Seed가 같고
When 여러 번 조합하면
Then 정규화된 일정 결과의 해시가 같다.

### AC-007 비용 안전

Given AWS 계정 플랜, Budget 수신 이메일 또는 배포 승인 중 하나가 없고
When production apply를 시도하면
Then 파이프라인은 AWS 리소스를 변경하기 전에 실패한다.

### AC-008 접근성

Given 키보드와 화면낭독기를 사용하는 사용자가
When 입력부터 출처 열기까지 진행하면
Then 포커스 순서, 오류 연결, 상태 알림과 버튼 이름을 이해할 수 있다.

### AC-009 우천 대체

Given 사용자가 우천 고려를 선택하고 승인된 실내 대체 후보가 있으며
When 일정을 조합하면
Then 시스템은 기본 일정의 하드 제약을 지키는 일자별 실내 대체 후보와 교체 시
이동시간 영향을 함께 표시한다.

## 4. 우선순위

- P0: FR-001~FR-020, NFR-001~NFR-015
- P1: FR-021과 출처 기반 AI 설명
- P2: FR-022~FR-023, 도시 확대, 사용자 저장 기능

## 5. 변경 통제

새 요구사항은 ID, 사용자 가치, 비용·법적 영향, 관련 DDD Context,
인수 조건과 테스트를 함께 추가해야 한다. P0 범위를 늘릴 때는 기존 출시
일정과 데이터 검수량을 다시 산정한다.
